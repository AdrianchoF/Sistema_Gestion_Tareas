Primero envié mi `db.ts` y comenté: "Asi lo hice, hice npm run dev, se levanto el servidor sin errores, pero no me salio ningun mensaje de conexion con la base de datos ni nada". - **Qué se aceptó y por qué:** El uso de `Pool` en lugar de `Client` (reutiliza conexiones entre peticiones, lo que conviene en una API). La función `testConnect` exportada, para decidir desde `index.ts` cuándo se ejecuta. La función `start()` con `async/await`, para no levantar el servidor si la base de datos no responde. El `index.ts` final lo generó la IA después de que no logré implementarlo yo; luego lo entendí línea por línea.
- **Qué se rechazó o modificó y por qué:** Mi primera versión de `db.ts` tenía varios errores que corregí tras la revisión: cerraba el pool con `pool.end()` (lo deja inutilizable después de la primera consulta), ejecutaba la prueba dentro del mismo archivo, importaba `config` desde `dotenv` en vez de mi Singleton, leía `process.env` directamente en lugar de `config.db`, y la consulta de prueba imprimía todos los usuarios con sus hashes de contraseña (cambiada por `SELECT NOW()`).
